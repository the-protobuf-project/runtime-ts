# @the-protobuf-project/protobuf

Protobuf messages in TypeScript, without classes or reflection. A message is a
plain interface in its protojson shape, and a `MessageCodec` converts it to and
from protojson and the binary wire format. Code generators such as
[protoc-gen-codemode](https://github.com/the-protobuf-project/codemode) emit one
codec per message on top of this package.

```sh
bun add @the-protobuf-project/protobuf
```

## Usage

### Use a generated codec

```ts
import { fromBinary, toBinary, toJsonString } from "@the-protobuf-project/protobuf";
import { type Book, BookCodec } from "./gen/library/v1/messages/book.ts";

const book: Book = { title: "Leaves of Grass", pageCount: "9007199254740993", createTime: "2026-11-22T10:00:00Z" };

BookCodec.fromJson({ title: "Odes", page_count: 120 }); // validates; accepts proto field names too
BookCodec.toJson(book); // protojson, defaults left out
BookCodec.toJson(book, { emitDefaults: true }); // every field written
const bytes = toBinary(BookCodec, book); // protobuf binary
fromBinary(BookCodec, bytes); // and back
toJsonString(BookCodec, book); // JSON text
```

Bad input fails with an `INVALID_ARGUMENT` `StatusError` whose message names
the field, such as `library.v1.Book.editions[0].year: expected an integer`.

### Well-known types

They map to their protojson form, so they need no wrapper types:

| Type                           | TypeScript                               | Codec                                         |
| ------------------------------ | ---------------------------------------- | --------------------------------------------- |
| `Timestamp`                    | `string` (RFC 3339)                      | `TimestampCodec`                              |
| `Duration`                     | `string` (`"1.5s"`)                      | `DurationCodec`                               |
| `FieldMask`                    | `string` (`"title,author"`)              | `FieldMaskCodec`                              |
| `Struct`, `Value`, `ListValue` | `JsonObject`, `JsonValue`, `JsonValue[]` | `StructCodec`, `ValueCodec`, `ListValueCodec` |
| wrappers (`StringValue`, ...)  | `T \| null`                              | `StringValueCodec`, ...                       |
| `Any`, `Empty`                 | `AnyMessage`, `Empty`                    | `AnyCodec`, `EmptyCodec`                      |

```ts
import { DurationCodec, TimestampCodec } from "@the-protobuf-project/protobuf";

TimestampCodec.fromJson("2026-11-22T12:00:00+02:00"); // "2026-11-22T10:00:00Z"
DurationCodec.decode(DurationCodec.encode("90s").finish()); // "90s"
```

### Enums and resource names

```ts
import { enumCodec, resourceName } from "@the-protobuf-project/protobuf";

type BookState = "BOOK_STATE_UNSPECIFIED" | "BOOK_STATE_LENT";
const BookStateCodec = enumCodec<BookState>("library.v1.BookState", [
  ["BOOK_STATE_UNSPECIFIED", 0],
  ["BOOK_STATE_LENT", 2],
]);
BookStateCodec.fromJson(2); // "BOOK_STATE_LENT"

const BookName = resourceName<"shelf" | "book", `shelves/${string}/books/${string}`>(
  "library.example.com/Book",
  "shelves/{shelf}/books/{book}",
);
BookName.format({ shelf: "poetry", book: "odes" }); // "shelves/poetry/books/odes"
BookName.parse("shelves/poetry/books/odes"); // { shelf: "poetry", book: "odes" }
```

### Any

`google.protobuf.Any` needs to know the packed type. Generated packages call
`registerTypes` on import; register hand-written codecs the same way.

```ts
import { AnyCodec, registerTypes, toBinary } from "@the-protobuf-project/protobuf";

registerTypes([BookCodec]);
toBinary(AnyCodec, { "@type": "type.googleapis.com/library.v1.Book", title: "Odes" });
```

### The wire format by hand

```ts
import { BinaryReader, BinaryWriter, WireType } from "@the-protobuf-project/protobuf";

const bytes = new BinaryWriter()
  .tag(1, WireType.LengthDelimited)
  .string("Odes")
  .tag(7, WireType.Varint)
  .int64("120")
  .finish();
const r = new BinaryReader(bytes);
const [field, wireType] = r.tag(); // [1, 2]
r.string(); // "Odes"
```

64-bit integers are strings throughout, as in protojson, so they keep full precision.
